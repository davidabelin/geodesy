1. Process starts in Google Earth: hand-selecting collections of points and exporting these in kml format, for example selected_points.kml,

2. Next, the kml is read by walk_kml.py, which outputs all the points from the kml into a csv file (with columns LOC, LAT, LON for each point), eg. selected_points.csv,

3. This is then run manually through geoinvrs.py to produce another csv, call it azdist_selected.csv, containing the azimuth and distance between _every combination_ of the selected point pairs . (A potentially explosize compute!) 

4. Then, this point-pair azimuth/distance data is imported into an Excel worksheet. There, I manually sort it and shift it and try to end up with a hundred or so "pairs of interest" (e.g. by how close the distance is to an exact 10th of a mile; or, the azimuth to an exact degree or half-degree; or, ... I have many more somewhat-automatable ways to implement in python for choosing which smaller sets of points to draw lines between, once we get the rest of the workflow more "optimized"!),

5. Once the "interesting" points have been chosen in Excel, they're exported to yet another csv file: linepairs.csv; here each row contains simply "Refpnt" and "Pnt", the string names of the paired points to have a line between,

6. Next, these pairs are read by pair_lines.py, which looks up the coordinates for each point in the pair from the reference file ref.csv, and outputs them to paired_lines.csv, now ready for input to:

7. draw_line_pairs.py, which reads the list of pairs and sequentially draws a line between them (assigning color and width for each according to logic I haven't settled on yet; but, it will change from what's in this file as provided), formatting the entire set of lines as a kml file, selected_lines.kml

8. And finally, this final kml file is imported into Google Earth for viewing.
